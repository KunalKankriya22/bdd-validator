How It Works

  • Serial Processing: Batches are processed one at a time using concatMap
  • UI Responsiveness: Uses macrotask queue yielding (asyncScheduler) to prevent UI freezing
  • Retry Logic: Failed batches are retried with exponential backoff
  • Cancellation: Processing can be cancelled at any time, stopping all pending operations
  • Resume: If enabled, processing can resume from the last successful batch after interruption
  • Progress Tracking: Real-time updates on processing status, percentage, and batch counts

Microtask vs Macrotask

Microtasks (Promises, RxJS operators) execute before browser rendering, which can freeze the UI when processing many batches. Macrotasks (setTimeout, asyncScheduler) allow the browser to render between operations, keeping the UI responsive even with hundreds of batches.

This implementation uses observeOn(asyncScheduler) to move batch emissions to the macrotask queue, ensuring the browser can paint between batches.
