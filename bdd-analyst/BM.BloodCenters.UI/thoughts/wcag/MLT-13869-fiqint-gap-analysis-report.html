High Severity Issues

1 Order Date, Ship Date, Interface Date missing time component High Field Display / Timezone
Current Behavior
Header: API formats OrderDate, ShipDate, InterfaceDate as date-only strings (MM-dd-yyyy). Angular displays "15-JAN-2024" without time.
Detail: Same issue — ShipDate and InterfaceDate are date-only. Only InsertDate includes time.
Expected Behavior
Oracle Forms POST-QUERY formats ALL date fields with time: to_char(v_local_time,'MM-DD-RR HH24:MI') → displays "01-15-24 14:30". Users rely on time to distinguish transactions occurring on the same day.
Root Cause
In FinanceInterfaceDetailsService.cs, ConvertHeaderToDtoAsync() formats OrderDate and ShipDate as "MM-dd-yyyy" (line 134-135) and InterfaceDate as "MM-dd-yyyy" (line 123). Only InsertDate includes "HH:mm:ss". Same pattern in ConvertDetailToDtoAsync() (lines 155, 166-167).
Suggested Fix
API only (no Angular change needed): In ConvertHeaderToDtoAsync(), change OrderDate and ShipDate format to "MM-dd-yyyy HH:mm:ss". Change InterfaceDate format to "MM-dd-yyyy HH:mm:ss". Apply same changes in ConvertDetailToDtoAsync(). The Angular formatDate() method already extracts and displays time when present in the string.
2 Order No dropdown does not display customer name in options High Dropdown / LOV
Current Behavior
Angular mat-select shows only opt.orderNo as the option text. Customer name appears separately below the dropdown only after an order is selected. Users searching for orders have no customer context while browsing the dropdown list.
Expected Behavior
Oracle Forms ODER_LOV displays 2 columns: "Order No" (150px) and "Name" (250px). Users can visually scan orders AND their customer names simultaneously, which is essential for identifying the correct order when multiple orders exist.
Root Cause
The template renders <mat-option [value]="opt.orderNo">{{ opt.orderNo }}</mat-option> — only the order number. The customerName property exists on OrderLookupDto and is already used for search filtering, but not displayed in options.
Suggested Fix
UI fix in finance-interface-details.html: Change the mat-option to: <mat-option [value]="opt.orderNo">{{ opt.orderNo }} — {{ opt.customerName }}</mat-option>. The search filter already supports customerName matching.

Medium Severity Issues

3 Order No restricted to dropdown — no free-text entry for orders outside 21-day window Medium Dropdown / LOV
Current Behavior
Angular uses mat-select populated with orders from the last 21 days only. Users MUST select from this list. Orders older than 21 days are completely inaccessible.
Expected Behavior
Oracle Forms S_ORDER_NO is a text input with an attached LOV. Users CAN type any order number manually (with Upper case restriction). The LOV shows recent 21-day orders as a convenience, but manual entry allows querying ANY order in the system. The KEY-NEXT-ITEM trigger validates against ORDERS + CUSTOMERS tables directly.
Root Cause
The Angular component uses mat-select (selection-only control) combined with the 21-day API filter, creating a hard restriction on queryable orders.
Suggested Fix
Options: (A) Change to mat-autocomplete which allows typed input AND dropdown suggestions, with server-side validation for typed values. (B) Add a "search older orders" mechanism or increase the rolling window. (C) Accept the 21-day limit as a deliberate modernization (requires product owner confirmation).
4 Insert Date field is dropdown-only — no free-text entry Medium Business Logic
Current Behavior
Angular uses mat-select for insert dates — user must pick from the list.
Expected Behavior
Oracle Forms S_INSERT_DATE is a text input with attached LOV (FormatMask: FXMM-DD-RR HH24:MI:SS). Users can type a date directly.
Root Cause
Same mat-select vs text-input design choice. Since the insert date dropdown shows ALL dates for the selected order (no date range filter), this is less impactful than Gap #3.
Suggested Fix
Lower priority. The dropdown already shows all available dates for the selected order. If needed, switch to mat-autocomplete for consistency.
5 Detail record count (DET_COUNT) not displayed in header section Medium Field Display
Current Behavior
Angular does not display the total detail record count in the header card. The count is only visible as "Record Type X of N" in the detail card's navigation area.
Expected Behavior
Oracle Forms shows DET_COUNT in the header block area: computed via SELECT COUNT(*) FROM serve_ar_interface_det WHERE order_no = :s_order_no AND chapter_id=:global.chapter_id AND insert_date = :serve_ar_interface_hdr.insert_date. Gives users immediate visibility into detail line item count.
Root Cause
The API returns TotalDetailCount in the response, and Angular has detailRecords().length available, but neither is rendered in the header card UI.
Suggested Fix
Add a "Detail Count" field to the header card: <div class="finance-interface-details__field-item"><div class="finance-interface-details__field-label">Detail Count</div><div class="finance-interface-details__field-value">{{ detailRecords().length }}</div></div>

Low Severity Issues

6 Insert Date display format uses 4-digit year vs Oracle's 2-digit year Low Field Display
Assessment
Angular uses MM-dd-yyyy HH:mm:ss (4-digit year) and DD-MMM-YYYY, HH:MM for record display. Oracle used MM-DD-YY HH24:MI:SS (2-digit year). The 4-digit year is an improvement — clearer and avoids ambiguity. No action required.
7 Detail navigation uses LEFT/RIGHT arrows vs Oracle's UP/DOWN arrows Low Business Logic
Assessment
Angular uses LEFT/RIGHT arrow keys plus clickable prev/next buttons. Oracle used UP/DOWN arrows with text messages. The horizontal navigation with buttons is appropriate for the card-based layout. No action required.
